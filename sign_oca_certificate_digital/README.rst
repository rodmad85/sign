Sign OCA Digital Certificate Authentication
===========================================

Complementary authentication provider for **Sign OCA**.

It verifies the identity of a signer with an ICP-Brasil X.509 digital
certificate before the electronic signature is accepted: the certificate
validity is checked, the signer proves possession of the private key by
signing a random challenge, and certificate data (subject, issuer,
serial number, CPF and expiration) is recorded for auditing.

The optional online revocation check (OCSP/CRL gateway) is the only
external service used and is fully mockable, so the module can be
installed and tested without real certificates or credentials.

Configuration
=============

Configuration
=============

Go to *Settings → Sign Oca → Digital Certificate Authentication*:

- **Require digital certificate authentication**: when enabled, every
  new sign request requires its signers to authenticate before signing.
  The requirement can still be toggled per request on the request form.
- **Certificate revocation endpoint**: optional URL of an OCSP/CRL
  gateway that receives ``{"serial_number": "..."}`` and returns
  ``{"revoked": false}``. Leave it empty to skip the online revocation
  check.

Usage
=====

Usage
=====

The signer portal issues a challenge through
``/sign_oca/certificate/challenge/<signer_id>/<access_token>``. The
signer signs that challenge with the private key of the certificate and
submits the PEM certificate, the base64 signature and the challenge to
``/sign_oca/certificate/verify/<signer_id>/<access_token>``.

The endpoint returns ``{"authenticated": true}`` on success or
``{"authenticated": false, "error": "..."}`` on failure. On success the
signer is marked as *Verified* and the usual Sign OCA signature flow is
allowed to continue. If the request requires this authentication and the
signer is not verified, ``action_sign`` is blocked.

The result is visible on the signer form under *Digital Certificate
Authentication*.

Known issues / Roadmap
======================

Roadmap
=======

- Apply a real PAdES signature to the PDF with a certified timestamp
  (pyHanko/endesive) instead of only authenticating the signer.
- Validate the full ICP-Brasil chain against the configured CA bundle
  and verify the certificate CPF against the partner's fiscal data.
