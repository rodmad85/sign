Sign OCA GOV.BR Authentication

Complementary authentication provider for Sign OCA.

It authenticates the signer with GOV.BR (Login Unico) using the OpenID Connect authorization-code flow: the signer is redirected to GOV.BR, the state/nonce are validated on the callback, the authorization code is exchanged for an access token and the identity (sub, CPF and trust level) is read from the userinfo endpoint and recorded on the signer.

All HTTP calls go through requests with an explicit timeout and are mocked in the tests, so the module can be installed and tested without real GOV.BR credentials.

Table of contents

Configuration

Configuration

Go to Settings → Sign Oca → GOV.BR Authentication and fill in the data of your Login Unico (GOV.BR) integration:

  • Client ID and Client Secret of the registered service.
  • Authorization endpoint, Token endpoint and Userinfo endpoint of the GOV.BR OpenID Connect provider (use the endpoints documented for the environment of your integration).
  • Require GOV.BR authentication: when enabled, every new sign request requires its signers to authenticate. The requirement can still be toggled per request on the request form.

Register https://<your-odoo-host>/sign_oca/govbr/callback as the allowed redirect URI of the GOV.BR client.

Usage

Usage

From the signer portal, open /sign_oca/govbr/auth/<signer_id>/<access_token> to start the authentication. GOV.BR redirects back to /sign_oca/govbr/callback, which validates the state, exchanges the code and records the signer identity.

On failure the callback returns to the signer page without marking the signer as verified, and the reason is stored on the signer. When the request requires GOV.BR authentication and the signer is not verified, action_sign is blocked with a clear error. The authentication result is visible on the signer form under GOV.BR Authentication.

Known issues / Roadmap

Roadmap

  • Validate the signed id_token (JWS) and the nonce against the stored value instead of relying only on the userinfo endpoint.
  • Map the GOV.BR CPF to the partner’s fiscal data and enforce the minimum reliability level (selo prata/ouro) per request.
