Clinical Management Sign OCA
============================

This module integrates **Sign OCA** with the clinical reports of
``clinical_management`` (model ``hospital.clinical.report``).

It allows the clinic to send a generated clinical report for electronic
signature, using the professional responsible for the report as the
signer, and stores the signed PDF back on the clinical report once every
signer has signed.

It follows the same integration pattern used by the OCA modules
``agreement_sign_oca``, ``crm_sign_oca`` and ``project_task_sign_oca``.

Configuration
=============

Configuration
=============

1. Install ``sign_oca`` and ``clinical_management`` (this module depends
   on both).
2. Make sure each professional (``hr.employee``) has a linked portal
   user (or a work contact). The linked partner is used as the signer of
   the request.
3. Upload the handwritten signature image of the professional on the
   *Professional (Clinical)* tab of the employee form; it is printed on
   the clinical report layout (``clinical_management``).
4. Set the **Signature Type** on each professional
   (``clinical_management``): ``Image`` (default),
   ``Digital Certificate`` or ``GOV.BR``. This module reads that choice
   when creating the sign request.
5. Install ``sign_oca_certificate_digital`` and/or ``sign_oca_govbr``
   for the authenticated types. They are checked dynamically (no hard
   dependency), but if the matching module is missing the request is
   refused with a clear message instead of producing an unauthenticated
   document.
6. For ``Digital Certificate``, register the A1 ``.pfx/.p12`` on the
   professional. The certificate password is requested on every emission
   by the ``clinical_management`` wizard and is never stored here.

Usage
=====

Usage
=====

Open a **Clinical Report** in *Draft* state and click **Request
Signature**.

Odoo renders the report PDF and creates a ``sign.oca.request`` linked to
the report, with the responsible professional as signer and the
*Healthcare Professional* role. Configure the signature fields, send the
request and sign it from the portal.

The professional's **Signature Type** decides the request: with
``Image`` both authentication flags are turned off (even if the company
enables them by default); with ``Digital Certificate`` or ``GOV.BR`` the
corresponding flag is turned on, so the signer must authenticate before
signing. For the certificate type, the A1 password wizard is shown first
and the request is only created after it is validated.

Once all signers have signed, the final PDF is copied to the **Signed
Clinical Report** field on the *Signature* tab and the report is set to
*Done*. The existing signature requests are reachable from the smart
button on the report form.
